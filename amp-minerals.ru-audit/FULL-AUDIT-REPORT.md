### Проблема самого замера

Проект TopVisor настроен так, что не может показать реальную картину:

1. **Один съём за всё время** (25.08.2026) → нет динамики, нельзя отследить эффект работ.
2. **Регион только «Россия» (225)** для обоих поисковиков. У сайта 5 городских лендингов
   (Екатеринбург, Челябинск, Тюмень, Пермь, Москва), но ни один регион не отслеживается.
   Региональная выдача Яндекса для «мраморная крошка купить» в Екатеринбурге — это
   совершенно другой топ, и там шансы кардинально выше.
3. **33 запроса** на 13 товаров × 5 городов × 6 применений — ядро не покрывает и 10%
   семантики из `lib/data/semantic-core.ts`.
4. Всё в одной группе «Новая группа» → нельзя считать видимость по кластерам.

### Топ-5 критичных проблем

1. **Нет H1 на `/delivery/` и `/contacts/`** — старшее заголовочное тегирование начинается с `<h2>`.
2. **У `Product` нет `offers`** — ни одна из 13 товарных страниц не может получить товарный
   сниппет ни в Google, ни в Яндексе.
3. **20 из 40 title длиннее 70 символов** — суффикс `| ЗАО «АМП ИМПОРТ-ЭКСПОРТ»` (26 симв.)
   съедает сниппет, обрезается до бессмысленного.
4. **Google-видимость = 0**, включая бренд. Нужна проверка индексации в GSC.
5. **`www.amp-minerals.ru` отдаёт 200** вместо 301 — раздвоение хоста (спасает только canonical).

### Топ-5 быстрых побед

1. Добавить H1 на `/delivery/` и `/contacts/` — 2 строки кода.
2. Убрать суффикс бренда из title у товарных и категорийных страниц, уложиться в 60 симв.
3. 301 с www на без-www на уровне nginx/Caddy.
4. Добавить `offers` (`AggregateOffer` + `priceCurrency` + `availability: InStock` +
   `url` + `seller`) в Product-разметку — цена по запросу оформляется через
   `PriceSpecification` без числа или через `priceValidUntil`.
5. Исправить llms.txt: «12 позиций» и «Семь фракций» против «13 позиций» и «8 фракций»
   в каталоге; **убрать строку про «фото пока не предоставлены» и «подписанные слоты»** —
   она прямо говорит AI-системам не доверять визуалу сайта.

- `FAQPage` — на товарных, категорийных, применениях, городских и `/about/`.

  `datePublished`, `dateModified`, `image` 1200×630.

- `LocalBusiness` — на `/contacts/` и 5 городских, с `geo`, `openingHoursSpecification`.

### Находки

| Severity | Проблема | Детали |
|---|---|---|
| **High** | У `Product` нет `offers` | Проверено на `/product/mramornyj-shheben-10-20/` и структурно одинаково на всех 13. Без `offers` Google не выдаёт товарный rich result вообще, Яндекс не строит товарную карточку. Цена «по запросу» — не препятствие: валидный вариант — `offers: { "@type": "AggregateOffer", "priceCurrency": "RUB", "availability": "https://schema.org/InStock", "url": "<страница>", "seller": {"@id": "<Organization>"} }`, либо `Offer` с `priceSpecification` без числового `price`. |
| Medium | `LocalBusiness` дублируется с одинаковым geo | 6 URL (`/contacts/` + 5 городов) содержат `LocalBusiness` с идентичными `address` (Екатеринбург, Савкова 29), `telephone`, `geo: 56.790945, 60.487171`. Правильнее: один `LocalBusiness` с `@id` на `/contacts/`, а на городских — `Service`/`Organization` с `areaServed`, ссылающийся на тот же `@id`. |

Поисковики не могут склеить их в один граф — каждая страница выглядит как новое объявление организации. Добавить `@id: https://amp-minerals.ru/#organization` и ссылаться на него из `publisher`, `manufacturer`, `seller`, `WebSite.publisher`. |
| Medium | Нет `Product.aggregateRating` / `review` | Отзывов нет ни в каком виде. Для B2B это норма, но у компании есть карточка в Яндекс.Картах — оттуда отзывы можно легально переносить и размечать. |

| Low | Нет `Organization.vatID` / `taxID` | Для ЗАО указание ИНН/ОГРН — сильный сигнал легитимности, особенно для Яндекса и для AI-систем при проверке «реальная компания или нет». |
| Low | Нет `WebSite.potentialAction` (SearchAction) | Поиска по сайту нет вообще — это отдельный UX-пробел для каталога из 13 позиций с фракциями. |
