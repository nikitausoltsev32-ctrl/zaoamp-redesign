# Семантика под «купить мраморную крошку» — федерально

Цель: занять топ по коммерческому ядру «мраморная крошка / щебень / микрокальцит купить»
без привязки к Екатеринбургу.

---

## Сначала о частотностях — честно

**Реальных цифр Wordstat в этом документе нет, и я их не придумываю.**

Что проверено:

1. **TopVisor частотность не собирал.** Модуль есть, поля
   `volume:0:225:1` (базовая), `volume:0:225:2` («фраза»), `volume:0:225:3` («!точная»),
   `volume:1:225:1` (Google) возвращают `null` по всем 33 запросам проекта 32272062.
   Собрать можно, но это платная операция и только для фраз, уже добавленных в проект —
   расширять ядро ей нельзя.
2. **В репозитории цифры есть, но это не Wordstat.** `lib/data/semantic-core.ts`,
   71 запрос с полем `frequency`. В шапке файла прямо написано: *«Частотности —
   ориентировочные оценки… собраны через research, НЕ выгрузка из Wordstat. Перед
   стратегическими решениями перепроверять вручную»*. На таких числах приоритизировать
   бюджет нельзя.

Поэтому ниже — **структура ядра и карта «запрос → страница»**, где приоритет выставлен по
интенту и по тому, есть ли под запрос страница. Колонка частотности заполняется после
получения доступа (см. `KEYS-NEEDED.md`, пункт 2). Структура от цифр не изменится —
изменится только порядок внутри групп.

---

## Главное, что нужно понять про «федерально»

**В Яндексе «мраморная крошка купить» без города — это не один топ, а разные топы для
каждого региона пользователя.** Человек в Новосибирске и человек в Краснодаре по одному и
тому же запросу видят разную выдачу: Яндекс подмешивает организации и сайты с привязкой к
региону посетителя.

Из этого три следствия:

1. «Быть первыми по купить мраморную крошку» = **быть первыми в каждом приоритетном
   регионе**, а не в одном федеральном списке. Отслеживать нужно по регионам.
2. Текущий замер в TopVisor (только регион «Россия», 225) в принципе не покажет прогресс
   по этой цели. Это не придирка к настройке — это несовпадение метрики с целью.
3. Единственный по-настоящему федеральный слой — это **бесгеовые запросы с интентом
   производителя**: «мраморная крошка от производителя», «карьер мраморной крошки»,
   «завод мраморной крошки». Там региональная подмешка слабее, а по данным Вебмастера
   (из `CLAUDE.md`) именно такие запросы у этого сайта уже конвертят. Это и есть точка,
   где производитель может обойти перекупщиков и агрегаторы.

Отдельно: по чисто коммерческому «мраморная крошка купить» федеральный топ занят
агрегаторами и маркетплейсами. Производителю выгоднее не лезть в лоб, а забрать
**«от производителя» + «карьер» + фракционные + отраслевые + региональные** — суммарно
это больше целевого трафика и кардинально выше конверсия.

## Кластер 6. Гео — где и живёт «федеральность»

Есть 5 городских страниц. Ни один геозапрос не отслеживается.

**Текущие:** Екатеринбург, Челябинск, Тюмень, Пермь, Москва.
Под каждый: «мраморная крошка <город>», «мраморный щебень <город>»,
«мраморная крошка купить <город>», «мраморная крошка цена <город>»,
«мраморный щебень с доставкой <город>», «микрокальцит <город>».

**Куда расширяться** (по логике логистики от карьера в Челябинской области):
Уфа, Курган, Магнитогорск, Оренбург, Нижний Новгород, Казань, Самара, Новосибирск,
Санкт-Петербург, Краснодар, Ростов-на-Дону.

Важная оговорка: **городские страницы нельзя размножать в текущем виде.** Сейчас 5 штук
по 420–472 слова на одном шаблоне с несклоняемыми топонимами («Основные направления для
Москва»). Клонировать это на 15 городов = получить фильтр за малополезный контент.
Сначала фаза 1 (уникализация), потом расширение.

Обязательное условие для геовыдачи, вне сайта: **проверить и настроить региональность в
Яндекс.Вебмастере** и добавить зоны обслуживания в Яндекс Бизнес.

## Порядок действий по семантике

1. **Собрать реальный Wordstat** — после получения доступа (`KEYS-NEEDED.md`, п. 2).
   Снимать три типа частотности: базовую, `"фраза"` и `"!точная"` — для коммерческих
   запросов решает именно точная, базовая раздута синонимией.
2. **Пересобрать `lib/data/semantic-core.ts`** на реальных числах, добавить поля под
   базовую/фразовую/точную вместо одного `frequency`, снять оговорку из шапки файла.
3. **Пересобрать проект TopVisor:** регионы Екатеринбург (54), Челябинск (56),
   Тюмень (55), Пермь (50), Москва (213) + Россия (225); группы по кластерам 1–8;
   150–200 запросов; недельный съём.
4. **Убрать мусорные запросы** из отслеживания (несуществующие фракции, термины без контента).
5. **Закрыть непокрытый спрос** новыми страницами (кластер 7) — после фазы 1, не раньше.
6. **Расширять гео** — только после уникализации текущих 5 городских страниц.
