# Офсайт-контент движок: автогенерация статей + ссылочное продвижение

**Дата:** 2026-06-22
**Статус:** утверждён к реализации

## Цель

Наращивать ссылочный авторитет домена `amp-minerals.ru` (приоритет) и приводить
прямой трафик через статьи на внешних авторитетных площадках (Дзен, VC.ru, Habr).
Аудитория — B2B (снабженцы, прорабы, технологи) и строители.

Контекст: домен новый (старт февраль 2026, SEO-контент с апреля-мая), в «песочнице»
Яндекса. Внешние ссылки — самый слабый фактор по GEO-аудиту (~62/100). Офсайт-статьи
дают backlinks, которых сейчас нет.

## Ключевое ограничение

Публичного API публикации у Дзена нет (закрыт для обычных аккаунтов, RSS-импорт
прикрыт). Дзен агрессивно детектит автоматизацию — капча, бан канала за роботность.
Поэтому **автопостинг через серверный API/Action исключён**. Публикация — ручная,
с опциональным экспериментом полуавтоматического постинга с локальной машины.

## Архитектура

Система делится на ядро (A, обязательное) и эксперимент (B, опциональный).
Они независимы: B можно не запускать, ядро работает.

### 1. Очередь тем — `content/topics.json`

Единственный источник правды: что писать и что уже сделано.

```json
{
  "queue": [
    {
      "slug": "mramornaya-kroshka-dlya-shtukaturki",
      "title": "Мраморная крошка для декоративной штукатурки: фракции и расход",
      "platform": "dzen",
      "audience": "b2b",
      "status": "pending"
    }
  ]
}
```

Поля:
- `slug` — латиница, для имени файла
- `title` — заголовок статьи
- `platform` — `dzen` | `vc` | `habr`
- `audience` — `b2b` | `builders`
- `status` — `pending` → `generated` → `published`

Жизненный цикл статуса:
- `pending` — тема в очереди, статья не написана
- `generated` — агент написал markdown-файл, ждёт публикации
- `published` — опубликована вручную (или скриптом B), URL вписан

### 2. Генератор — scheduled агент

Запуск через `/schedule`, 2 раза в неделю (Дзен любит регулярность; 2×/нед —
баланс роста и риска спама).

Алгоритм каждого запуска:
1. Прочитать `content/topics.json`.
2. Взять первую тему со `status: pending` и `platform: dzen`
   (Дзен — приоритет автопубликации; VC/Habr пишутся реже, см. ниже).
3. Сгенерировать B2B-статью: markdown + frontmatter.
4. Вставить в тело 1–2 контекстные ссылки на `amp-minerals.ru` (товар/категория,
   релевантные теме). Не спамные, в смысловом месте.
5. Сохранить в `content/{platform}/YYYY-MM-DD-{slug}.md`.
6. Сменить статус темы на `generated`.
7. Коммит + пуш в ветку `content/auto` (НЕ в `main`).

Пользователь периодически просматривает `content/auto`, правит/одобряет и мержит
в `main` сам. Облачный агент в `main` напрямую не пишет — ревью остаётся за человеком.

VC.ru и Habr: агент пишет такие темы реже (когда в очереди нет pending-Дзен или
по явной пометке темы), кладёт в их папки. Их пользователь публикует руками —
у этих площадок жёсткая модерация, автопостинг не предусмотрен.

### 3. Формат файла статьи

```markdown
---
title: "Мраморная крошка для декоративной штукатурки: фракции и расход"
platform: dzen
audience: b2b
status: generated
backlinks:
  - "https://amp-minerals.ru/product/mramornaya-kroshka-0-2"
published_at:
url:
---

# Заголовок

Текст статьи…
```

После публикации пользователь (или скрипт B) меняет `status: published`,
вписывает `published_at` и `url`.

Стиль статьи под B2B:
- практическая польза (расход, фракции, технология, выбор поставщика)
- без «воды» и кликбейта
- реальные числа из паспортов качества (белизна 98%, CaCO₃ 98%, Аэфф 72 Бк/кг —
  см. memory product_specs)
- ссылки на сайт в контексте, не в конце списком

### 4. Эксперимент B — `scripts/dzen-post.mjs`

Опциональный полуавтоматический постинг. Запуск **только с машины пользователя**
(`npm run post:dzen`), не на сервере — чтобы IP и сессия выглядели человеческими.

Поведение:
1. Загрузить сохранённую сессию Дзена (`storageState`, авторизация заранее вручную).
2. Найти самый свежий файл со `status: generated` и `platform: dzen`.
3. Открыть редактор Дзена в Playwright, ввести заголовок и текст с человеческими
   задержками.
4. Если появляется капча/антибот — остановиться, не публиковать, вывести сообщение
   «опубликуй вручную».
5. При успехе — заполнить `status: published` + `url` в файле.

Скрипт изолирован: ядро A от него не зависит. Если Дзен забанит автоматизацию,
удаляем скрипт, ядро продолжает работать.

## Структура файлов

```
content/
  topics.json                       # очередь тем (источник правды)
  dzen/
    2026-06-25-slug.md
  vc/
    2026-06-30-slug.md
  habr/
    2026-07-03-slug.md
scripts/
  dzen-post.mjs                     # эксперимент B (Playwright, локально)
docs/superpowers/specs/
  2026-06-22-offsite-content-engine-design.md
```

`package.json` → добавить скрипт `"post:dzen": "node scripts/dzen-post.mjs"`.

## Что НЕ делаем (YAGNI)

- Нет официального API Дзена (закрыт).
- Нет серверного автопостинга (GitHub Action / cron на сервере) — бан канала.
- Нет Supabase под темы — `topics.json` достаточно.
- Нет PR-ревью пайплайна — убивает автоматизацию; при плохом контенте добавим позже.
- Нет сторонних платных посредников (Make.com, ApiMonster) — «через подписку».

## Как измерять успех

- **Ссылки:** Яндекс.Вебмастер → «Внешние ссылки»; GSC → Links → External.
  Цель — рост числа ссылающихся доменов.
- **Трафик с площадок:** Яндекс.Метрика → источник «Переходы по ссылкам на сайтах»,
  отдельно дзен/vc/habr.
- **Косвенно:** рост Impressions в GSC и позиций по коммерческим запросам по мере
  выхода из песочницы (август-октябрь 2026).

## Риски

- Дзен забанит даже полуавтопостинг (B) → fallback на полностью ручную публикацию,
  ядро A не страдает.
- Низкое качество автогенерации → добавить ручное ревью перед сменой статуса.
- Массовая публикация выглядит как спам → держать темп 2×/нед, не больше.
