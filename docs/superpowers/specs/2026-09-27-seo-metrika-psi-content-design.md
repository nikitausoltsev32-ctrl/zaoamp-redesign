# Метрика без согласия, PageSpeed, семантика и страницы применения

Дата: 2026-09-27. Статус: дизайн утверждён пользователем в чате, спец ждёт ревью.

## Зачем

Данные 27.09.2026 (`Seo/data/2026-09-27/`):

- **Метрика слепая.** Счётчик монтируется только после «Принять» в cookie-баннере
  (`components/cookie-consent.tsx`, решение из спеки 2026-07-04). За 90 дней Метрика
  видит 56 визитов, из поиска 2, из Google 0 — при 22 кликах в GSC. Нельзя оценить ни
  одну SEO-правку по поведению и заявкам; Яндекс не получает поведенческих данных.
- **Мобильная скорость.** PSI mobile: производительность 75–84, LCP 3,8–4,9 с на пяти
  ключевых страницах. Десктоп 96–99. TTFB ~80 мс, CSS уже brotli — узкое место на клиенте.
- **Яндекс выкидывает страницы применения.** В поиске 19 из 48 (−14%).
  `/primenenie/landshaft/`, `/lkm/`, `/shtukaturka/` исключены как LOW_QUALITY 26.09 —
  третий цикл с июля. Переобход не лечит, нужна содержательная доработка.
- **Wordstat собран, но не использован.** `Seo/semantic/frequency-results.csv`
  (1278 запросов, 23.09) не разнесён в `core.csv`/`clusters.csv`.

## Блок 1. Метрика

- `components/cookie-consent.tsx`: `<Script id="yandex-metrika" strategy="afterInteractive">`
  рендерится всегда, без условия `consent === 'accepted'`. Параметры `ym(...init...)` те же.
- Баннер: текст «Сайт использует cookie и Яндекс.Метрику…» + ссылка на `/privacy/` +
  одна кнопка «Понятно». Показ — пока нет записи в `localStorage` (ключ и срок 365 дней те же).
  Старое значение `rejected` у вернувшихся посетителей больше не блокирует счётчик.
- `app/privacy/page.tsx`: абзац про cookie/Метрику привести в соответствие
  (информирование, а не согласие до загрузки; как отключить — настройки браузера /
  блокировщик). Остальной текст не трогаем.
- `lib/analytics.ts` не меняется: `reachGoal` уже вызывает `window.ym`, теперь он будет всегда.
- В `<head>` — `<link rel="preconnect" href="https://mc.yandex.ru">`.

**Проверка:** dev + prod-сборка: в HTML/DOM есть скрипт `tag.js?id=108746641` без клика;
`window.ym` определён; баннер закрывается «Понятно» и не возвращается. После деплоя —
через 1–2 дня в Метрике появляются визиты с источником Google.

## Блок 2. PageSpeed (mobile)

**Цель:** медиана двух прогонов PSI mobile ≥ 90 и LCP < 2,5 с (лабораторно) на
`/`, `/catalog/kroshka/`, `/catalog/muka/`, `/product/mramornaya-kroshka-5-10/`,
`/blog/kak-vybrat-frakciyu-mramornoj-kroshki/`. Accessibility без ошибок контраста.
Цель — ориентир; если упрёмся в ограничение Next 14.1, фиксируем достигнутое и причину.

Находки Lighthouse (`Seo/data/2026-09-27/psi-audits.json`) и что делаем:

1. **Render-blocking CSS (~1 с).** Сначала замер LCP-элемента и цепочки запросов
   (Lighthouse trace / Playwright). Кандидат — `experimental.optimizeCss` (critters) в
   Next 14.1. Если в App Router не даёт эффекта — отказываемся и пишем почему.
2. **Шрифты.** Inter + Merriweather (400/700), оба preload. Проверить, где Merriweather
   нужен на первом экране; убрать неиспользуемые начертания/preload. Шрифты не меняем.
3. **Контраст.** `text-muted-foreground` и ссылки хлебных крошек, кнопка Telegram на
   главной — минимальный сдвиг токена `--muted-foreground` до AA 4.5:1. Палитру не меняем.
4. **Target size.** Поле `#volume` в калькуляторе на главной — высота/отступы до 44px зоны.
5. **Legacy JS (11 KiB).** `browserslist` в `package.json` под современные браузеры.
6. **Неиспользуемый JS (22 KiB) и тяжёлое на первом экране.** Проверить, что
   `AiAssistantWidget`, `MotionProvider`/framer-motion не тянут код в первую загрузку;
   если да — `next/dynamic` / отложенная загрузка без изменения поведения.
7. **Forced reflow** — выявить источник; править только если очевиден и безопасен.

**Проверка:** `tsc`, `next lint`, `next build`; `next start` + PSI нельзя (локалка) →
Lighthouse локально через Playwright/Chrome для сравнения до/после; на проде после
деплоя — `psi.mjs` медиана 2 прогонов. Визуально: скриншоты 5 страниц до/после
mobile+desktop — без изменений, кроме контраста.

## Блок 4. Контент страниц применения и `/catalog/kroshka/`

- Черновик — только факты сайта и паспортов (`memory/product_specs.md`), позиционирование
