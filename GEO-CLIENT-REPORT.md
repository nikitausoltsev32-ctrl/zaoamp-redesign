## Анализ цитируемости

### 5 наиболее цитируемых страниц

**1. /catalog/kroshka/ — Мраморная крошка**  
Страница имеет структуру вопрос-ответ, FAQPage schema, конкретные числа (8 фракций, цены от 3 000 ₽/т), BreadcrumbList. Технические спецификации (CaCO₃ ≥98%, белизна 98%) — именно такой фактический контент AI-системы охотно цитируют. Улучшение: добавить сравнительную таблицу «мраморная vs гранитная крошка» с конкретными числами по белизне, pH, радиации — это высокоцитируемый формат.

**2. /catalog/shcheben/ — Мраморный щебень**  
Аналогично сильная страница. FAQPage schema, фракционный справочник, цены. Улучшение: добавить раздел «Нормы расхода по типу применения» с таблицей т/м² — практические данные из собственного производства резко повышают E-E-A-T и вероятность цитирования.

**3. /blog/kak-vybrat-frakciyu-mramornoj-kroshki/**  
Структурированная статья с H2/H3 по применениям, конкретные технические детали, связанные продукты. Лучший кандидат для Google AIO прямо сейчас. Улучшение: добавить имя автора («Никита Усольцев, технолог с 20-летним стажем»), дату обновления, ссылку на паспорт качества.

**4. /primenenie/landshaft/ — Ландшафтный дизайн**  
Тематическая лендинговая страница с FAQPage и Application schema. Хорошо структурирована под конкретный поисковый интент. Улучшение: добавить реальные фото объектов с подписями («жилой комплекс в Екатеринбурге, 2024»).

**5. /documents/ — Паспорта качества**  
Уникальная страница: фактические лабораторные данные (Аэфф 72 Бк/кг, CaCO₃ 98%) недоступны у большинства конкурентов. AI-системы любят первичные источники данных. Улучшение: добавить текстовое резюме каждого паспорта в HTML (а не только PDF) для лучшей индексации.

### 5 наименее цитируемых страниц

**1. /about/ — О компании**  
«20+ лет», «1000+ отгрузок» — без имён, без фото, без конкретных людей. AI-системы не могут верифицировать компанию без именованных сущностей. Решение: добавить имя директора, технолога, краткие биографии с реальным опытом.

**2. /blog/ — Список статей**  
Только заголовки и аннотации, нет авторов ни на одной статье. Для Google и ChatGPT блог без автора — анонимный контент с низким E-E-A-T. Решение: добавить имя автора на все 4 статьи, обновить Article schema с типом Person.

**3. City-лендинги (/ekaterinburg/, /chelyabinsk/ и др.)**  
Вероятно дублирующий контент с заменой только названия города. Поисковики и AI снижают ценность таких страниц. Решение: для каждого города добавить уникальный контент — условия доставки именно в этот регион, примеры объектов, LocalBusiness schema с city-specific адресом.

**4. /delivery/ — Доставка**  
Информационная страница без FAQ, без конкретных сроков по маршрутам, без тарифов. AI не может извлечь полезный ответ на «сколько стоит доставка мраморной крошки в Москву». Решение: добавить FAQ с реальными маршрутами и ценами, FAQPage schema.

**5. /contacts/ — Контакты**  
LocalBusiness schema реализована корректно, но страница тонкая — только координаты. Решение: добавить блок «Как добраться», ссылку на Яндекс Карты, часы работы с праздниками.

Ваши наиболее цитируемые страницы — лучшие кандидаты для появления в AI-ответах уже сейчас. Улучшение 5 наименее цитируемых страниц — наиболее высокая отдача от вложений в контент с точки зрения AI-видимости.

**Единственная техническая рекомендация с высоким приоритетом:** Реализовать IndexNow для мгновенного уведомления Bing (и через него ChatGPT) о новом контенте. Это 2-3 часа разработки с использованием готовой Next.js интеграции.

### Что исправить (2 изменения, ~2 часа работы)

**1. Добавить sameAs в Organization schema:**
```json
"sameAs": [
  "https://t.me/usolst",
  "https://yandex.ru/maps/org/[id]",
  "https://2gis.ru/ekaterinburg/firm/[id]",
  "https://www.b2b-center.ru/market/[id]"
]
```
Добавлять ссылки по мере регистрации на платформах — каждая новая ссылка усиливает граф сущностей.

**2. Изменить автора в Article schema с Organization на Person:**
```json
"author": {
  "@type": "Person",
  "name": "Никита Усольцев",
  "url": "https://amp-minerals.ru/about/"
}
```
Это повышает E-E-A-T сигнал для блога и может увеличить вероятность цитирования в Google AIO.

### Глоссарий

| Термин | Определение |
|---|---|
| GEO | Generative Engine Optimization — оптимизация контента для цитирования AI-поисковиками |
| AIO | AI Overviews — блоки AI-ответов в верхней части выдачи Google |
| E-E-A-T | Experience, Expertise, Authoritativeness, Trustworthiness — критерии качества контента Google |
| SSR | Server-Side Rendering — генерация HTML на сервере, необходимая для чтения AI-краулерами |
| JSON-LD | Формат структурированных данных Schema.org, рекомендованный Google |
| sameAs | Свойство Schema.org — ссылки на профили сущности на других платформах |
| IndexNow | Протокол мгновенного уведомления Bing о новом контенте |
| llms.txt | Файл-стандарт для предоставления AI-системам структурированного контекста о сайте |
| FAQPage | Тип Schema.org для разметки FAQ — ключевой для Featured Snippets и AI Overviews |
| BreadcrumbList | Schema.org разметка навигационной цепочки страниц |
| Knowledge Panel | Карточка компании в правой части выдачи Google — сигнал авторитетности для Gemini |
| Passage Retrieval | Технология Google/AI для извлечения конкретного абзаца из длинной страницы |
